### 3c. A fair two-noise IMM, "IMM2" (session B)

**Design.**
- IMM2 is the library's IMM, variant B1, with its own constants file. Nothing in the frozen library changes; κ_CA is not used.
  - It mixes two modes: the B3 CV filter and the B4 CA filter, with CANMOT arithmetic as frozen.
  - Transition diagonal 0.95 per 0.5 s; initial mode probabilities (CV, CA) = (0.9, 0.1).
- **Quiet mode (CV):** car Q = κ_q · Q of record.
- **High mode (CA):** acceleration noise σ_a² = σ²_hi.
  - Its position and velocity terms come from the same CV diagonal (library rule), so the two modes differ in noise only through the CA mode's acceleration states.
- R, ca_acc_init_var = 10 and every other class are the constants of record (`shared\trackers\trk_constants_v01.json`).
- The constants file is `B_retrack\out\imm2t\IMM2_CONSTANTS_v01.json`.

**Tuning: 20 lead-braking tuning runs only (`run_index_m4_v02.csv`: set = tune, family = lead_braking, use = 1).**
- **Statistic: A10 B3 rule (2), as frozen in `b3_nis_tune_v01.run_stat`, restricted to one truth phase.** Per run:
  - The lead track is the re-tracked planner actor matched to the true lead at each decision of record. On these runs it is always the scenario target: 20 of 20 runs, every decision.
  - Its updates are those with frame index ≤ the largest state frame at which it was matched.
  - Keep the updates whose detector frame lies in the phase; take their mean position NIS, ν′S⁻¹ν (ν = z[0:2] − x_prior[0:2], S = P_prior[0:2,0:2] + R_rot[0:2,0:2]).
  - Take the median over the runs with at least one such update; that number of runs is reported.
- **Identity check, before any search:** with all phases kept, the restricted statistic reproduces the frozen one bit for bit on the 20 runs at the constants of record (median 1.99443; `IMM2_TUNE_CHECK_v01.json`).
- **Truth phases of a detector frame at simulation tick k:**
  - k_on = the first tick whose scenario request time (assessment_time_s, `scenario_frames.jsonl`) is ≥ the case's brake_start_s (`contract.json`, case.draw);
  - k_stop = the first tick ≥ k_on at which the true lead (the `evaluation_truth` target) has speed ≤ 0.5 m/s (VMIN of record);
  - pre: k < k_on; braking: k_on ≤ k < k_stop; stopped: k ≥ k_stop.
  - This matches the truth phase of record (`trk_arrays_v01`, oxsb_extract_v05) at every tick whose request time is logged. Ticks before the first logged request count as pre.
- **κ_q:** variant B3 (the CV filter alone), pre frames. Grid κ = 10^(−3 + 0.05 j), j = 0…120 (A10 B3's grid).
- **σ²_hi:** variant B4 (the CA filter alone, on the CV diagonal of κ_q), braking frames. Grid 10^(−3 + 0.05 j), j = 0…160, with κ_CA = 1.
- **Search, for each parameter:**
  - Evaluate the grid in order. Take the first sign change of (median − 2), then bisect on log10 until |median − 2| ≤ 0.01.
  - With no sign change, take the grid value whose median is nearest 2. The text then says the window was not reachable on that phase.
- **Code:**
  - `B_retrack\code\b_imm2_tune_v01.py` (modes check, kq, sa2);
  - outputs `B_retrack\out\imm2t\IMM2_TUNE_{CHECK,KQ,SA2}_v01.json`.
- **F0 for IMM2:** its own P̄ on the 120 tuning runs (A10 §2.1; the rule of record `trk_arrays_v01.pbar_accumulate`, as for B1r).
- **Lock:** before LOCK_A12a, and before any IMM2 value on any evaluation run (new or C), the following are frozen in FREEZE_B addenda:
  - the constants, tuning outputs and code;
  - the Sonnet second programs;
  - then P̄_IMM2, as a data addendum.
- **Second IMM implementation (A10 §10.1(b)):** the five fresh runs of record (0288, 0324, 0384, 0450, 0582) with IMM2's constants. The library and `imm2\imm2_v02.py` must match: ids identical, P9 within 1e-9 relative.

**Scoring.** Open loop, 3 s, gridless frontier, all evaluated decisions, on IMM2's own room (F0 = P̄_IMM2; A10 §2.1). The keys are those of the IMM's row of Table III, as for IMMr.
- **Run sets:**
  - the new lead-braking runs of §2 (**primary**);
  - the 105 fresh C runs (**secondary**). IMM2 was specified after the C results of B1 and B1r were seen; the new runs are unseen.
- **Arrays:**
  - Re-track every run with IMM2 (`retrack_capture(cap, 'B1', const = IMM2's constants)`); extract with P̄_IMM2 exactly as for B1r.
  - Then a data manifest with SHA-256, written before scoring.
- **Values per run set:**
  - RR_gl(N_IMM2) and its interval;
  - IMM2's amplitude-matched ranking oracle c (E5 at IMM2's own median ratio and spread; not a bound);
  - RR − c, R, RR_CK3, within5, room by estimated phase, lag;
  - H3's class with δ = 0.05.
- **Bootstrap:** run-level, 20,000 resamples.
  - C runs: `boot_counts(105, 20000, 20261911)`, the C draw.
  - New runs: the new-run draw fixed in §2, shared by all §3 analyses. If §2 fixes none: `boot_counts(n_new, 20000, 20261922)`, runs in ascending id order.
- **Primary statistic, for §4's Holm.** The hypothesis "IMM2's covariance recovers part of its own room on the new runs" is tested by RR_gl(N_IMM2) > 0.
  - One-sided bootstrap p = (1 + #{b : RR*_b ≤ 0}) / (K + 1), K = 20,000, on the new-run draw.
  - The class is printed as H3 assigns it; Holm applies to this p only.
- **Permuted twin (descriptive).** A11 §6b's construction is applied to IMM2's arrays:
  - f_i = median over rows with finite positive g*_F0,r and g*_N,r of (g*_F0,r / g*_N,r)^½;
  - K = 20 permutations of f_i within each run, `default_rng(20261931)` drawn once, runs ascending;
  - Δ = RR_gl(N_IMM2) − RR_gl(IMM2p) on the same resample.
  - A percentile interval only, without A10 §2.6 calibration. IMM2's test is its class, not Δ.
- **Mode probabilities by truth phase (descriptive).**
  - Which decisions: every evaluated decision whose lead is matched to a re-tracked track.
  - μ_CA = that track's CA-mode probability after its last update or miss at or before the decision's detector frame (the tracker's mode record).
  - Grouped by the decision's truth phase of record: pre, braking, stopped.
  - Printed per phase: the mean of μ_CA, its median, and the share of decisions with μ_CA > 0.5, with run-level percentile intervals on the same draw.
  - Printed for IMM2 on both run sets. Also for B1r (and B1 as first tuned) on the C runs, as a descriptive reference.

**What is printed.**
- IMM2's row beside the IMM as first tuned and IMMr. These values stand.
- RR, c, their intervals and the class; Δ to the twin; μ_CA by phase.
- The tuning outcome: κ_q, σ²_hi, the medians reached, and whether each window was reached.
- p, and its Holm-adjusted value in §4's table.
- The C-run values are labelled secondary and disclosed as specified after the IMM's C results were seen.
