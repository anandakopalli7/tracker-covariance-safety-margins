## Points of the specification that needed a reading

1. **Which true actors and frames.** `ol_extract_v01.window_truth` takes the actors present at the decision frame and follows each over its contiguous true frames (it stops at the first frame without the actor). The same was done beyond frame 60. In these 35 runs there is one true actor per run, present in every frame, with constant extents, so no other reading can change a number.
2. **"Censored"** was taken literally as late and J > kmax - k. The extended clearance of a censored pair is the minimum over the frames that exist, so a censored pair with extended clearance <= 0 is a definite contact and one with > 0 is undetermined. The count of flag changes includes the censored ones (given separately above).
3. **Frames after the stop** (j > J) are not examined: a contact after the ego has come to rest is not counted, as specified.
4. **"Ratio to the 3 s denE"** (optional part) can mean the 3 s commitment scoring or the reaction-and-stop scoring on the 3 s window; both are given; the first program's `denE_over_3s` is the former.
5. `oc.poly_dist` returns 0 for overlapping or touching rectangles, so "clearance <= 0" means clearance = 0.
6. **What the agreement covers.** As the specification directs, the position profile comes from the code of record (`replan_s`, `brake_profile`) and the distances from `oc.rect_corners` / `oc.poly_dist`. The bit-identical values suggest the first program calls the same functions. The agreement therefore checks the extension logic (frames used, last frame J, late and censored flags, truth window, counting, and in the optional part the scoring), not those shared functions; an error inside them would not show here.
